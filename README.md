# 红包口令解读规范

本文档说明如何从下发的 `uint8` 数组中正确解读出红包口令。**必须按规范用环形缓冲区还原，不能直接按顺序读取。**

---

## 一、你拿到的数据长什么样

这是 **已置乱** 的字节：

```
48 6c 36 ac 6c 32 4d 65 6f 52
```

**不能**把字节当口令直接读——顺序是打乱的，直接读会得到乱码或 CRC 校验失败。

---

## 二、逻辑包格式（还原后）

还原后的**逻辑包**格式为：

| 部分        | 含义                       |
| ----------- | -------------------------- |
| 前 N-1 字节 | 口令（ASCII/UTF-8 字节）   |
| 最后 1 字节 | CRC8 校验值（多项式 0x07） |

例如假设口令为 `"HelloWorld"`，则还原后前 10 字节为该字符串的字节表示，最后一字节为 CRC8。

---

## 三、解读步骤（必须按顺序执行）

### 步骤 1：环形缓冲区还原

- 设收到的字节数为 **L**，将收到的 L 个字节**按到达顺序**依次放入环形缓冲区 `ring[0]` ~ `ring[L-1]`。
- 步长常量：**RING_STEP = 7**。
- 从下标 **cursor = 0** 开始，依次取 L 次：
  - 取出 `ring[cursor]` 作为**逻辑包**的下一个字节；
  - 然后 `cursor = (cursor + RING_STEP) % L`。
- 得到的 L 个字节即为还原后的逻辑包：**前 (L-1) 字节 = 口令，第 L 字节 = CRC8**。

### 步骤 2：CRC8 校验

- 对还原后的**前 (L-1) 字节**计算 CRC8（多项式 **0x07**，即 CRC-8）。
- 与还原后的**第 L 字节**比较：
  - **相等**：校验通过，继续步骤 3；
  - **不相等**：数据被篡改或传输出错，解读失败，不输出口令。

### 步骤 3：输出口令

- 校验通过后，将还原后的**前 (L-1) 字节**按字节解释为字符串（如 ASCII），即为红包口令。

---

## 四、对比：直接读 vs 按规范解读

| 数据                                     | 解读方式                                               | 结果                                           |
| ---------------------------------------- | ------------------------------------------------------ | ---------------------------------------------- |
| 未置乱的逻辑包（如直接转化得到的字节流） | **直接按顺序读**：前 N-1 字节为口令，最后 1 字节为 CRC | ✅ 可读，且 CRC 正确时即为正确口令              |
| 已置乱的字节流                           | **直接按顺序读**                                       | ❌ 顺序被置乱，不是逻辑包，CRC 不通过或得到乱码 |
| 已置乱的字节流                           | **先环形缓冲区步长 7 还原，再 CRC，再取前 N-1 字节**   | ✅ 得到正确口令                                 |

因此：**只有按「环形缓冲区 + 步长 7 还原 → CRC 校验 → 取前 N-1 字节」的规范，才能从置乱数据中正确解读口令。**

---

## 五、工程中的用法

- 本仓库提供 C++17 实现，头文件 `include/red_packet.hpp`、源文件 `src/red_packet.cpp`。
- 解码调用：`red_packet::decode(data, len)`，内部已按上述规范完成环形缓冲区还原、CRC8 校验与口令提取；成功返回口令字符串，失败返回空串。
